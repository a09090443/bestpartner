# BestPartner 系統操作手冊產生器（由 E2E 證據撰寫）

## Overview

把既有 **E2E 測試確認表的操作步驟**與 **`e2e-shots/` 的逐步截圖**，改寫成**給一般使用者看的系統操作手冊**，輸出至 `docs/manual/`。

核心原則一句話：**手冊只寫「已被 E2E 走過、且有截圖為證」的操作**。沒有證據的畫面不憑印象補寫，一律標為「待補畫面」並回報。

## When to Use

- 使用者說「寫操作手冊」、「產生使用手冊」、「依 E2E 更新手冊」
- 新功能完成一輪 E2E 後，要把新旅程納入手冊
- 手冊某章節畫面過舊，要用最新一輪 E2E 截圖翻新

## 事實來源（權威順序）

| 來源 | 用途 | 權威性 |
|------|------|--------|
| `docs/test-confirmations/e2e-test-confirmation-*.md` | 操作步驟、預期結果、狀態 | **步驟與行為的權威** |
| `docs/test-confirmations/e2e-shots/<時戳>/` | 畫面證據 | **畫面的唯一來源** |
| `docs/e2e-test-plan.md` §3 旅程矩陣 | 章節涵蓋範圍對照 | 範圍權威 |
| `.Codex/rules/api-endpoints.md`、`docs/workflow-engine/` | 行為說明的技術核對 | 佐證，不直接抄進手冊 |
| `bestpartner-ui/src/`（訊息字串、表單標籤） | 使用者實際看到的文案 | 用詞權威 |

> ⚠️ 只有 **✅ Pass** 的案例可寫成「正常操作步驟」。❌ Fail 案例不得寫入手冊；⏭️ Skip 案例當作無證據。

## 產出位置與檔案佈局（固定，不得自行更動）

```
docs/manual/
├── README.md                    # 手冊首頁：適用版本、章節索引、證據來源總表
├── 01-login.md                  # 登入與登出
├── 02-workflow-list.md          # 流程清單：建立 / 開啟 / 刪除
├── 03-canvas-editing.md         # 畫布編輯：拖節點 / 連線 / 存檔 / 版面與主題
├── 04-node-settings.md          # 節點設定：Inspector 與節點編輯頁
├── 05-validate-activate.md      # 檢查與啟用流程
├── 06-execute.md                # 執行流程與查看結果（含多觸發點）
├── 07-knowledge-rag.md          # 知識庫問答（RAG）
└── 99-troubleshooting.md        # 常見提示訊息與排除方式
```

- **圖片不複製、不另存**：一律以相對路徑直接引用既有證據截圖
  `![畫面說明](../test-confirmations/e2e-shots/<時戳>/<檔名>.png)`
  （理由：截圖已進版控，複製會產生同一畫面的兩份真相，日後翻新只更新一處會漂移。）
- 章節不足以成篇時**寧可不建立該檔**，也不要產生只有標題的空殼章節。

## 章節 ↔ E2E 旅程對照（撰寫範圍的唯一依據）

| 手冊章節 | 取材旅程 | 章節主題（使用者任務視角） |
|---------|---------|------------------------|
| `01-login.md` | J1 | 登入、登出、未存檔時登出的確認、登入失敗提示 |
| `02-workflow-list.md` | J2 | 檢視流程清單、建立新流程、開啟既有流程、刪除流程 |
| `03-canvas-editing.md` | J3、J9（縮放 / 主題 / 版面） | 從節點面板拖入節點、拉線連接、存檔、縮放與淺深色切換 |
| `04-node-settings.md` | J6、J9（節點編輯頁） | 右側設定面板填寫各型別節點、雙擊開啟節點編輯頁、引用上游輸出 |
| `05-validate-activate.md` | J4、J7 | 啟用前的檢查規則、常見擋下原因與修正方式、版本衝突 |
| `06-execute.md` | J5 | 執行流程、查看執行結果面板、多觸發點選擇入口、從節點卡執行 |

## Process（必須依序執行）

### Step 1：盤點證據

```powershell
# 所有 E2E 報告（新到舊）
Get-ChildItem docs/test-confirmations/e2e-test-confirmation-*.md | Sort-Object Name -Descending
# 每個時戳目錄的截圖清單
Get-ChildItem docs/test-confirmations/e2e-shots -Directory | ForEach-Object { "$($_.Name): $((Get-ChildItem $_.FullName).Count)" }
```

建立一張**證據索引**（暫存於 scratchpad，不進 repo）：`caseId → 報告檔 → 截圖檔清單 → 狀態`。
**同一案例有多輪證據時取最新一輪**（畫面較貼近現況）；若最新一輪該案例標「—未執行」，往前回溯至最近一次 ✅。

### Step 2：確認本次範圍

向使用者確認（只問這兩項，其餘自行判斷）：

```
- 本次要寫 / 更新哪些章節（預設：證據足夠的全部章節）
- 手冊適用的服務版本（預設取最新報告的「服務版本」欄）
```

### Step 3：逐章撰寫

每章結構固定為：

```markdown
# <章節標題>

> 適用版本：0.1.8 ｜ 畫面擷取自 E2E 驗證：<報告時戳>

<一段話說明這章能幫使用者完成什麼>

## <任務一：以使用者目的命名，如「建立一個新流程」>

**使用情境**：<何時會用到>

1. <操作步驟，祈使句，說明點哪裡、填什麼>

   ![<中文畫面說明>](../test-confirmations/e2e-shots/<時戳>/<檔名>.png)

2. <下一步>

   ![<中文畫面說明>](../test-confirmations/e2e-shots/<時戳>/<檔名>.png)

**完成後你會看到**：<可觀察的結果，取自 E2E 的「預期」欄>

> 💡 <小提醒，取自 E2E 備註中對使用者有意義的部分>
```

撰寫規範（違反即需重寫該段）：

1. **使用者視角用詞**：畫面上看得到的字才能當名詞（「執行結果面板」、「節點面板」）。
   `data-test`、`nodeKey`、SSE 事件名、API 路徑、i18n key **不得出現在正文**；確有必要時放章末「技術附註」摺疊區。
2. **步驟必須可回溯**：每個步驟都對應 E2E 某案例的某一步。撰寫時在 scratchpad 記錄對照，收尾回報時附上。
3. **圖片緊跟步驟**：一步一圖，圖放在該步驟之下；不得整章末尾堆圖，不得一張圖代表多步。
4. **引用前先確認檔案存在**（`Test-Path`）。**嚴禁寫出不存在的圖片路徑**——手冊裡的破圖比缺圖更糟。
5. **錯誤訊息照抄使用者實際看到的文字**（後端訊息查 `messages_zh_TW.properties`，前端寫死字串查 `bestpartner-ui/src/`），不寫 `workflow.skill.node.not.mounted` 這類 key。
6. **不杜撰**：E2E 沒走過的分支、沒截到的畫面，不憑程式碼推測寫成操作步驟。

### Step 4：處理缺畫面

證據不足時，於該處插入明確標記，**不得留空、不得以文字描述充當畫面**：

```markdown
> 📷 **待補畫面**：<需要什麼畫面> — 目前 E2E 證據未涵蓋（<缺的旅程/案例>）。
```

並在收尾回報列出完整「待補畫面清單」，供使用者決定是否加測該案例。

> ⚠️ 本 skill **不啟動服務、不自行補拍截圖**。要補畫面請走 `e2e-test-confirmation` skill 新增案例後再回來更新手冊。

### Step 5：截圖衛生檢查（強制）

引用每一張圖前，先確認畫面內容：

| 檢查 | 處置 |
|------|------|
| 含 API key / JWT / 密碼 / 資料庫連線字串 | **不得引用**，標為待補畫面 |
| 含 `e2e-` 前綴等測試殘留名稱 | 可用，但圖說須註明「圖中流程名稱為測試資料，實際請自行命名」 |
| 畫面明顯過舊（與現行 UI 不符） | 不引用，標為待補畫面並註明過舊 |

### Step 6：更新 `docs/manual/README.md`

必含三部分：

1. 手冊適用版本與最後更新日期
2. 章節索引（連結 + 一句話說明）
3. **證據來源總表**：每章 → 取材的 E2E 報告時戳 → 涵蓋旅程。這張表是日後判斷「哪章該翻新」的依據，不可省略。

### Step 7：收尾回報

回報：新增／更新的章節檔清單、各章取材的報告時戳、**待補畫面清單**、截圖衛生檢查中被排除的圖、以及本次未涵蓋的旅程與原因。

## 常見錯誤

| 錯誤 | 正確做法 |
|------|---------|
| 依程式碼或印象推測操作步驟 | 只寫 E2E ✅ 案例走過且有截圖的步驟 |
| 把 ❌ / ⏭️ 案例寫成正常流程 | 排除；⏭️ 視同無證據 |
| 手冊裡出現 `data-test` / nodeKey / SSE 事件名 | 換成畫面上的中文名詞，技術細節移到章末附註 |
| 把截圖複製一份到 `docs/manual/images/` | 一律相對路徑引用 `e2e-shots/`，避免兩份真相 |
| 缺畫面時用文字描述補上 | 插入「📷 待補畫面」標記並列入回報清單 |
| 為湊齊章節建立空殼檔 | 證據不足就不建該章 |
| 寫 i18n key 當錯誤訊息 | 抄 `messages_zh_TW.properties` 的實際中文 |
| 依 J1–J9 逐旅程分章 | 依使用者任務分章（見對照表），跨旅程整併步驟 |
| 引用不存在的圖片路徑 | 寫入前 `Test-Path` 逐一確認 |

## 維護規則

- **UI / 流程行為變更後**：先更新 `docs/e2e-test-plan.md` 與跑 `e2e-test-confirmation` 取得新截圖，**再**用本 skill 翻新對應章節。順序顛倒會讓手冊描述新行為卻配舊畫面。
- **章節結構異動**時同步 `docs/manual/README.md` 的證據來源總表與本檔的章節對照表。
- 手冊屬使用者文件，與 `docs-site/` 的開發者文件**刻意分離**：docs-site 講「系統怎麼設計」，本手冊講「使用者怎麼操作」，兩者不互相複製內容。
