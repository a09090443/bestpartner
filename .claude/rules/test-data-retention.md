# 測試資料保留詢問（測試收尾強制）

> 適用於**兩條**測試流程：API 測試（`test-confirmation` skill）與 E2E 測試（`e2e-test-confirmation` skill）。
> 本檔是「測試完成後資料要清或要留」的單一事實來源；兩個 skill 的收尾步驟引用本檔，不另訂規則。

## 核心規則

**所有測試案例執行完畢後、清理測試資料之前，必須以 `AskUserQuestion` 詢問使用者本次資料的處置方式。**
不得逕自清理（使用者可能還要接著手動驗證），也不得逕自保留（殘留髒資料視為流程不完整）。

> ⚠️ 未詢問即清理或即保留，視同測試流程違規。

### 詢問時機

| 流程 | 位置 |
|------|------|
| API 測試 | 所有模組測完、摘要更新完 → **詢問** → 清理／保留 → 關閉服務 |
| E2E 測試 | 所有選定旅程測完（含重測輪次）→ **詢問** → 清理／保留 → 關閉服務 |

失敗分流與修正若導致多輪重測，**只在最後一輪收尾時詢問一次**；中間輪次的前置清理照既有規則走。

### 選項（至少提供三種）

| 選項 | 行為 |
|------|------|
| 全部清理（預設建議） | 依既有清理規則刪除本次建立的所有資料 |
| 全部保留 | 不清理，供使用者後續手動測試 |
| 部分保留 | 列出本次建立的資料讓使用者挑，未選中者清理 |

**詢問時必須附上「本次建立了什麼」的清單**（資源類型／名稱／id），使用者才有判斷依據。
清單來源是執行過程中**逐筆記錄下來的 id**，不是事後掃描猜的（見下方「唯一安全依據是 id」）。

## 使用者選擇「保留」時

1. **不執行清理**（該筆資料的刪除 API 不呼叫，兜底掃描也要排除）。
2. **改名以避開兜底掃描**：E2E 建立的 workflow 命名為 `e2e-<caseId>-<runTag>`，而收尾與後續輪次會以
   `e2e-<runTag>` 前綴兜底掃描刪除。保留的資料**必須改名成不含 `e2e-` 前綴的名稱**
   （建議 `keep-<runTag>-<原名>`），否則日後任何一輪的兜底掃描會把它清掉。
3. **寫入確認表**：在「測試資料處置」欄位記錄決議、保留清單（類型／名稱／id）、保留理由。
4. **收尾回報明示**：回報中列出保留了哪些資料、放在哪、日後如何自行清理。
5. **後續清理責任歸使用者**：不得在後續測試輪次的前置或兜底清理中自動刪除已核准保留的資料。

## 使用者選擇「清理」時

依各流程既有的清理規則執行：

- **唯一安全依據是本次執行記錄下來的 id**，不可依名稱樣式、日期或「孤兒」條件批次刪除
  （實際事故：曾以 `name === '未命名流程'` 為條件清理，刪掉了使用者自己的流程）。
- 不得另建備份檔／目錄；備份資料只能寫入 `docs/sql/bestpartner-init-data.sql`
  （見 [`documentation-update-policy.md`](documentation-update-policy.md)）。
- 種子資料（`admin`、`test_user` 及其 LLM setting）為前置條件，永不刪除。
- 逐步截圖屬報告證據，隨報告保留，**不在清理範圍**。

## 保留資料 ≠ 保留服務

**無論使用者選擇保留或清理，收尾一律關閉服務**（後端 port 80、前端 5173/4173），
port 淨空才算收工（E2E 由 `e2e-flow-guard.ps1` 的 Stop hook 實測把關）。

選擇保留時，回報中必須附上重啟指令，供使用者手動測試時自行啟動：

```bash
# 後端（dev profile；-D 參數必須在 -jar 之前）
cd bestpartner-service && java -Dquarkus.profile=dev -jar build/bestpartner-service-0.1.8-SNAPSHOT-runner.jar
# 前端（E2E 情境）
cd bestpartner-ui && npm run preview
```

## 常見錯誤

| 錯誤 | 正確做法 |
|------|---------|
| 測完直接清理，事後才說「已清理」 | 清理前先用 `AskUserQuestion` 問，等回覆再動手 |
| 問了但沒附本次建立的資料清單 | 附上類型／名稱／id，使用者才有判斷依據 |
| 使用者說保留就整批不刪，連沒必要的中間資料也留著 | 提供「部分保留」選項，逐項確認 |
| 保留的 workflow 沿用 `e2e-<runTag>` 名稱 | 改名成不含 `e2e-` 前綴（如 `keep-<runTag>-…`），避開兜底掃描 |
| 使用者要保留資料，就順手把服務也留著 | 服務一律關閉，回報附重啟指令 |
| 每輪重測都問一次 | 只在最後一輪收尾詢問一次 |
